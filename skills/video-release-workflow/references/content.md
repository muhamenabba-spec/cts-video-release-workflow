# 文案与拍摄

## 恢复最少的真实材料

先从已有对话和项目取得受众、业务、核心观点、素材来源、时长意图和拍摄方式。仅缺会改变写法的信息才问；新用户可以先问“这条主要给谁看、想让他明白什么”，不要一上来索要全套账号历史。

区分本人经历、用户转述、第三方案例、假设算例、待证事实。数字和论断标注来源；可变的价格、平台规则、产品条件需查当前权威来源。素材不足可以缩小结论，不编订单、收益、客户评价或个人立场。

本包提供创作判断，不复制付费课程。接收者自己提供的知识库或已安装内容方法，可以按工作区规则调用；未读原文不能声称已经使用。没有这些资料也不能虚称依赖作者私有知识库。

## 一条讲清一个主要问题

先用一句话写出观众能得到的东西，再选择结构：

- 观点：具体事件或冲突 → 判断 → 为什么 → 证据与适用边界。
- 经历：先露出真实冲突/结果 → 当时怎么想 → 实际发生什么 → 现在怎么判断。
- 方法/答疑：具体问题 → 卡在哪里 → 可实行的一小步 → 怎么判断有效。
- 测评：真实测试疑问 → 判断标准 → 过程和结果 → 对谁适合。
- 过程：今天要做什么 → 真实阻碍 → 尝试 → 当下结果或明确的后续。

这不是要求机械填满每格。口播要能一口气说得顺，先讲具体人和事，再抽出观点。删“底层逻辑、认知跃迁、价值闭环”等没有实际解释作用的词，不用宏大结尾替代结果。

## 开头与持续观看理由

开头优先让目标观众认出自己的问题，再交代值得继续看的冲突、证据、结果或具体收获。联合检查第一画面、首句、字幕与声音，不靠一句空泛“今天给大家讲一下”。

只迁移对标的问题切口和节奏，不复制专属经历、数字或长段独特表达。用户已指定开头时保留，指出真实逻辑或口误问题再做必要的微调；不要把“更安全”作为削弱已能兑现的冲突的理由。

教程有证据、后续、具体交付和可视预览时，可借它们连续给观看理由；经历、观点、复盘不能因此硬套教程模板。

独立检查：开头让谁愿意看；正文给了什么新判断/证据/办法；标题和封面承诺是否兑现。检查不是播放量预测，不能保证爆款。

## 两种拍摄交付

**提词器模式**：给可直接口播的完整正文；需要屏幕示例时另列对应画面，不把剪辑指令混进嘴里要说的话。

**自由发挥模式**：给开头原句、推进要点、一个真实例子、结尾意思。保留用户自己的口头习惯；完整版仅作备用，不要求照读。实拍以用户真正说出的内容为准，原稿不是强制逐字覆盖字幕的答案。

控制时长以实际语速/样片估算，标为估计，不宣布固定字数等于固定秒数。用户要求简短，只保留支撑本条观点必需的案例；用户要讲清楚，也不能无理由拉成多观点长课。

## 确认与 CTA

交初稿后允许确认定稿或指定改动。已确认观点不静默改写。用户只改错字就做错字层修改，保存版本差异。

CTA 非固定片尾。有真实互动目的可留一个相关提问；没有就自然结束。不同时索要点赞、关注、私信、收藏；不编福利、回复保证或站外导流。

脚本确认不代表发布确认。写完后若用户尚未拍摄，交稿并停在等待视频，不生成不存在的成片。
